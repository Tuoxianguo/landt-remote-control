# 蓝电（LAND）测试柜远程控制上位机

> 基于《蓝电远程控制及数据获取协议 V3.0》开发的 **HTTP 远程控制上位机**，
> 一个 Python 单文件图形程序：可远程 **启动 / 续接 / 停止** 测试通道、录入**电池条码**、
> 实时查询通道**状态与测试参数**，并可一键打包成 exe 在其它电脑直接使用。

---

## 一、这是什么

很多场景下需要用外部软件去控制蓝电电池测试柜、读取自定义数据。本项目实现了蓝电官方协议的
**全部 3 个 HTTP 接口**，并封装成一个带中文界面的桌面程序，支持 8 通道（1×8）批量操作。

| 协议接口 | 功能 | 本软件对应操作 |
|---|---|---|
| `POST /OpearMon/control` | 远程 **启动 / 续接 / 停止** 通道（含电池条码、活性质量、比容量、极性、备份方案） | 勾选通道 → 「▶启动 / ⏯续接 / ■停止」 |
| `POST /QueryChlStatus/control` | 获取通道**状态**（测试中/停止/完成/故障/无状态） | 「立即刷新 / 自动刷新」 |
| `POST /QueryChlRP/control` | 获取通道**实时参数**（电压/电流/容量/循环/工步/温度等） | 「立即刷新 / 自动刷新」 |

---

## 二、功能特性

- ✅ **全协议覆盖**：启动 / 续接 / 停止 + 状态查询 + 实时参数查询，一个程序全部搞定。
- ✅ **电池条码录入**：每个通道单独录入条码（`strBattNo`），并可设活性物质质量、标称比容量。
- ✅ **8 通道 1×8 表格**：每行一个通道，可勾选后批量操作，状态彩色高亮。
- ✅ **自动查找主机**：自动探测 LANDMon 的 HTTP 服务 IP（解决服务只绑定局域网 IP 的坑）。
- ✅ **多箱体自动识别**：自动扫描所有箱体并选中“有有效通道”的箱体（箱号可下拉切换）。
- ✅ **防限流**：内置请求节流 + 退避重试，妥善处理服务端“防频繁请求(QC)”限流。
- ✅ **配置持久化**：IP/端口/箱号/条码/工艺路径等自动保存，下次打开即用。
- ✅ **离线自测**：附带协议模拟服务器，无真机也能演示和联调。
- ✅ **一键打包**：PyInstaller 打包成单个 exe，目标电脑无需安装 Python。

## 三、系统架构（务必先看懂）

```
 ┌──────────┐   COM 口(如COM7)   ┌─────────────────────────┐   HTTP:7777   ┌────────────────┐
 │  测试柜   │ ───────────────► │ 蓝电监控软件 LANDMon.exe │ ◄──────────► │ 本软件（上位机） │
 │ (硬件)    │                  │ （本机开放 7777 端口）   │              └────────────────┘
 └──────────┘                  └─────────────────────────┘
```

- **串口（如 COM7）是「LANDMon ↔ 测试柜硬件」之间的连接**，不是本软件直接连串口。
- 本软件通过 **HTTP** 与 `LANDMon.exe` 通讯，由它再去控制测试柜。
- 运行本软件前，**必须先打开 `LANDMon.exe` 并连上测试柜**。
  （`CLANDTestDlg.exe` 只是启停小工具；提供 7777 HTTP 服务的是 `LANDMon.exe`。）

> ⚠️ **HTTP 服务不一定绑定在 `127.0.0.1`。** 实测可能绑定在局域网 IP（如 `172.16.2.233`），
> 此时填 `127.0.0.1` 会报「目标计算机积极拒绝」。**点「自动查找主机」即可自动定位正确 IP**（启动时也会自动执行）。

## 四、通道号与多箱体

协议用两个字段共同定位一个通道：

- **nBox（箱号）**：基于 1。
- **nChl（通道号）**：基于 1，范围 **[1, 8]**。

通道标识格式为 `箱号(3位)_通道号`，例如 `002_8` = 第 2 箱第 8 通道。

> ⚠️ 一台 LANDMon 可能管理**多个箱体**（nBox = 1,2,3…），但通常只有一个箱体真正接了硬件
> （其余箱体通道全为“无状态”）。本软件连接后会**自动扫描并选中有效箱体**，你的 8 个通道就显示在该箱内；
> 也可用顶部「箱号」下拉框手动切换。

## 五、快速开始

### 方式 A：直接使用打包好的 exe（推荐给现场使用）

1. 从本仓库 **Releases** 下载 `蓝电测试柜远程控制上位机_vX.X.zip` 并解压。
2. 先运行 `LANDMon.exe` 并连上测试柜。
3. 双击 `LANDT测试柜远程控制.exe`：
   - 程序自动「查找主机 + 扫描箱体」，顶部变绿「● 已连接」、箱号自动选到有效箱；
   - 在表格里勾选通道、输入**电池条码**、选好 `.spi` 工艺与备份目录；
   - 点 **「▶ 启动选中」**，日志出现「[成功] 启动成功 (nCode=0)」即成功。

### 方式 B：从源码运行

```bash
pip install requests
python landt_app/landt_control.py
```

### 离线自测（无真机时）

```bash
python landt_app/landt_mock_server.py   # 启动模拟服务器(默认7777)
# 再打开上位机，主机填 127.0.0.1、端口 7777 即可联调
```

## 六、界面说明（简版）

- **连接设置**：主机 IP / 端口、自动查找主机、测试连接、自动刷新 + 间隔(秒)、立即刷新。
- **启动参数**：箱号、极性（正/反）、SchemeFlag、PartA 前缀、测试工艺(.spi)、备份目录。
- **通道表格**：选择、通道标识、条码、活性质量、比容量、状态、电压、电流、容量、循环、工步、工步时间、温度、备份文件名。
- **运行日志**：记录每次操作与返回码（**判断成功以 `nCode=0` 为准**）。

完整图文手册见 [`landt_app/使用说明书.md`](landt_app/使用说明书.md)。
**在另一台电脑通过局域网 TCP/HTTP 远程接入**，见 [`landt_app/远程接入文档.md`](landt_app/远程接入文档.md)。

## 七、SchemeFlag（备份文件名组合）

SchemeFlag 为 **4 位数字**：

| 位 | 取值 | 含义 |
|---|---|---|
| 第 1 位 | 0/1 | 启用 / 弃用 **PartA**（前缀名） |
| 第 2 位 | 0/1/2/3 | 弃用PartB / 通道启动日期 / **电池条码** / 电池条码_通道启动时刻 |
| 第 3 位 | 0/1/2 | 弃用PartC / **通道号**(如 `_003_8`) / PartC_Alias |
| 第 4 位 | 0/1 | 名字顺序 AB_C / A_C_B |

**默认 `1210`**：弃用PartA、用电池条码作PartB、用通道号作PartC → 备份文件名形如 `电池条码_002_8`。

---

## 八、状态码 / 错误码

- **通道状态 nStatus**：`0`测试中　`1`停止　`2`完成　`3`故障　`4`无状态
- **操作返回 nCode**：`0`=成功；**负数**=失败（`strMsg` 为原因，如限流 `Reject frequent requests`）

---

## 九、关于请求限流（重要）

LANDMon 服务端有「防频繁请求」限流，请求过密会返回 `nCode=-1, Reject frequent requests(QC)`。
本软件已内置**全局节流（串行 + 最小间隔）与命中限流自动退避重试**，默认刷新间隔 **5 秒**。
若日志仍提示 QC，请把「刷新间隔」调大到 8~10 秒。

## 十二、常见问题

| 现象 | 解决 |
|---|---|
| 连不上 127.0.0.1 / 「目标计算机积极拒绝」 | 点「自动查找主机」，软件会找到真实 IP（如 172.16.2.233） |
| 连接失败 / 一直未连接 | `LANDMon.exe` 没开、没连上串口、端口错、防火墙拦 7777 |
| 日志出现 `Reject frequent requests / QC` | 服务端限流，软件会自动退避重试；可调大刷新间隔 |
| 启动返回负数 nCode | `.spi` 路径在 LANDMon 电脑上不存在、通道已在测试、参数非法 |
| 表格全是「无状态」 | 当前箱号是空箱，用箱号下拉框切到有效箱（一般会自动选中） |
| 跨电脑连不上 | 两机需同一局域网，且 LANDMon 电脑防火墙放行 7777 |
