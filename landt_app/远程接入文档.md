# 蓝电测试柜 · 局域网远程接入文档

> 目标：在**另一台电脑（B）**上，通过局域网 TCP/IP 远程控制**蓝电主机（A）**，
> 完成测试通道的 **启动 / 续接 / 停止**、以及 **状态 / 实时参数** 读取（协议全部功能）。
>
> 本文档包含：网络拓扑、IP 规划示例、防火墙放行、连通性验证、图形软件接入、代码接入（任意语言），以及排错。

---

## 0. 一句话原理

蓝电主机 A 上的 `LANDMon.exe` 会开一个 **HTTP 服务（端口 7777，运行在 TCP 之上）**。
所谓“通过 TCP 远程控制”，就是 **B 通过局域网向 `http://A的IP:7777` 发送 HTTP 请求**（POST/JSON）。
协议本身就是 HTTP-over-TCP，**没有另外的裸 TCP 协议**，所以用任何能发 HTTP 的工具/语言都能接入。

```
┌───────────────┐        局域网 (同一网段)         ┌────────────────────────────┐   COM7   ┌────────┐
│  电脑 B        │  HTTP/TCP  →  http://A:7777      │  电脑 A（蓝电主机）         │ ───────► │ 测试柜 │
│ 远程控制端     │ ─────────────────────────────► │  LANDMon.exe (HTTP:7777)    │          │ (硬件) │
│ (上位机/代码)  │ ◄───────────────────────────── │  绑定在局域网IP上           │          └────────┘
└───────────────┘        返回 JSON (nCode/数据)    └────────────────────────────┘
```

---

## 1. 角色与本机实测参数

| 角色 | 说明 | 本次实测值（示例，以你现场为准） |
|---|---|---|
| **A = 蓝电主机** | 运行 `LANDMon.exe`，接测试柜(COM7) | IP `172.16.28.132`，子网掩码 `255.255.255.0`(/24)，网关 `172.16.28.254` |
| **B = 远程控制端** | 运行上位机软件 / 自己写的代码 | 需与 A 同网段，示例 IP `172.16.28.100` |
| **服务端口** | LANDMon 的 HTTP 服务 | `7777`（TCP） |

> ⚠️ A 有两张网卡（有线“以太网2” = `172.16.28.132/24`，无线 WLAN = `172.16.10.10/23`），
> **LANDMon 只绑定在有线网卡 `172.16.28.132` 上**。因此 **B 必须能访问 `172.16.28.x` 这个网段**。

---

## 2. 【A 侧 · 第一步】确定并**固定**蓝电主机的 IP（最重要）

### 2.1 查看 LANDMon 当前绑定的 IP/端口
在 A 上用管理员 PowerShell 执行：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 7777 | Select-Object LocalAddress,LocalPort,OwningProcess
```
输出里的 `LocalAddress` 就是 B 要连接的 IP（本次为 `172.16.28.132`）。

### 2.2 ⚠️ 务必把 A 的 IP 固定下来
实测：A 的 IP **昨天是 `172.16.2.233`，今天变成了 `172.16.28.132`** —— 这是 DHCP 自动分配导致的。
**如果不固定，B 上配置的 IP 隔天就会失效。** 二选一：

**方案一（推荐）：在路由器/交换机里做“DHCP 地址保留（MAC 绑定）”**，让 A 每次都拿同一个 IP。

**方案二：给 A 设置静态 IP**（需与现网段一致，且该 IP 未被占用）：
```powershell
# 1) 先看网卡名字（找到有线那张，如“以太网 2”）
Get-NetAdapter | Select-Object Name,Status,MacAddress

# 2) 设置静态IP（示例：接口名"以太网 2"）
New-NetIPAddress -InterfaceAlias "以太网 2" -IPAddress 172.16.28.132 -PrefixLength 24 -DefaultGateway 172.16.28.254
Set-DnsClientServerAddress -InterfaceAlias "以太网 2" -ServerAddresses 172.16.28.254
```
> 设静态 IP 有网络中断风险，建议现场网管操作；拿不准就用方案一。
> 固定后，`LANDMon.exe` 每次启动都会绑定到这个固定 IP，B 的配置就长期有效。

---

## 3. 【A 侧 · 第二步】放行防火墙 7777 端口（否则 B 连不进来）

实测 A 上**没有**针对 7777 的入站放行规则，Windows 防火墙默认会**阻止**远程连入。
在 A 上用**管理员** PowerShell 执行（二选一）：

**PowerShell 方式：**
```powershell
New-NetFirewallRule -DisplayName "LANDMon HTTP 7777" -Direction Inbound -Protocol TCP -LocalPort 7777 -Action Allow -Profile Any
```

**netsh 方式：**
```powershell
netsh advfirewall firewall add rule name="LANDMon HTTP 7777" dir=in action=allow protocol=TCP localport=7777
```

**（可选，更安全）只允许本网段访问**，把放行范围限制在 `172.16.28.0/24`：
```powershell
New-NetFirewallRule -DisplayName "LANDMon HTTP 7777" -Direction Inbound -Protocol TCP -LocalPort 7777 -Action Allow -Profile Any -RemoteAddress 172.16.28.0/24
```

> 删除该规则（如需回退）：
> ```powershell
> Remove-NetFirewallRule -DisplayName "LANDMon HTTP 7777"
> ```

---

## 4. 【B 侧 · 第三步】配置 B 的网络，使其与 A 同网段

B 的 IP 必须和 A 在**同一网段**（示例网段 `172.16.28.0/24`），网关一致，IP 不冲突。

### 示例 IP 规划表

| 设备 | IP 地址 | 子网掩码 | 默认网关 | 说明 |
|---|---|---|---|---|
| A（蓝电主机） | `172.16.28.132` | `255.255.255.0` | `172.16.28.254` | LANDMon 绑定在此 IP |
| B（远程控制端） | `172.16.28.100` | `255.255.255.0` | `172.16.28.254` | 任选一个本网段内未被占用的 IP |

- 如果 B 是**自动获取(DHCP)**且已在 `172.16.28.x` 网段，通常无需改动，直接进下一步。
- 如需在 B 上**手动设置**（示例，接口名以实际为准）：
```powershell
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 172.16.28.100 -PrefixLength 24 -DefaultGateway 172.16.28.254
```

> 若 A、B 不在同一网段，需要路由器在两个网段之间放通路由；最省事的做法是把 B 接到与 A 相同的交换机/网段。

---

## 5. 【B 侧 · 第四步】验证网络连通性（三连测）

在 B 上执行，**逐项通过**再继续：

```powershell
# (1) 能 ping 通 A（若被禁ping可跳过，看第2步为准）
ping 172.16.28.132

# (2) 关键：测试 7777 端口是否可达（返回 TcpTestSucceeded : True 即成功）
Test-NetConnection 172.16.28.132 -Port 7777

# (3) 直接调一次“查询状态”接口（返回 JSON 即打通）
curl -X POST http://172.16.28.132:7777/QueryChlStatus/control -H "Content-Type: application/json" -d "{}"
```

- `Test-NetConnection` 显示 `TcpTestSucceeded : True` = TCP 到 7777 已通。
- 若为 `False`：多半是**防火墙没放行(回第3节)** 或 **不在同网段/IP填错(回第2、4节)**。

## 6. 【B 侧 · 方式一】用图形软件接入（最简单，推荐现场用）

1. 把本项目的发布包 `蓝电测试柜远程控制上位机_v1.0`（含 `LANDT测试柜远程控制.exe`）**整个拷贝到 B**。
2. 在 B 上双击运行 `LANDT测试柜远程控制.exe`。
3. 顶部【连接设置】里：
   - **主机IP** 填 **A 的 IP**：`172.16.28.132`
   - **端口**：`7777`
   - 点 **「测试连接」**，看到绿色「● 已连接」即成功。
   > 注意：B 上的 **「自动查找主机」只扫描 B 本机的网卡**，找不到 A；**跨机必须手动填 A 的 IP**。
4. 连接后，顶部「箱号」下拉会列出箱体，软件会自动选中有效箱（现场实测为 **箱 2**）。
5. 之后所有操作与本机一致：勾选通道 → 填**电池条码** → 选 `.spi` 工艺与备份目录 → 「▶启动/■停止」；
   状态与实时参数会自动刷新。

> 工艺文件(.spi)、备份目录这些路径，指的是 **A（蓝电主机）本机上的路径**，不是 B 的路径。

## 7. 【B 侧 · 方式二】用代码/命令接入（任意语言，完成全部功能）

统一规则：向 `http://172.16.28.132:7777/<接口>` 发送 **POST**，**请求体为 JSON**，**返回体为 JSON**。
**判断成功以返回的 `nCode == 0` 为准**（负数=失败，`strMsg` 为原因）。

### 7.1 通道号规则（重点）
- `nBox`＝箱号（基于1），`nChl`＝通道号（基于1，范围 **1~8**）。
- 通道标识形如 `002_8` = 第2箱第8通道。
- 一台 LANDMon 可能有多个箱体，**真正接硬件的通常只有一个**（本现场为 **箱2**），其余箱体通道为“无状态”。

### 7.2 接口一：启动 / 续接 / 停止 —— `POST /OpearMon/control`
请求字段：`nOperaType`(0启动/1续接/2停止)、`CycModeReverse`(0正/1反极性)、`strBackupDir`、`strSpiFullPath`(.spi，启动必填且须在A本机存在)、`SchemeFlag`(4位，默认"1210")、`PartA`(前缀)、`MultipleChls`[{`nBox`,`nChl`,`strBattNo`电池条码,`ActMass`活性质量,`SpeCap`比容量}]。

**启动 箱2 的 通道1、2（带电池条码）——curl：**
```bash
curl -X POST http://172.16.28.132:7777/OpearMon/control -H "Content-Type: application/json" -d "{\"nOperaType\":0,\"CycModeReverse\":0,\"strBackupDir\":\"D:\\\\1\",\"strSpiFullPath\":\"D:\\\\1\\\\LAND.spi\",\"SchemeFlag\":\"1210\",\"PartA\":\"\",\"MultipleChls\":[{\"nBox\":2,\"nChl\":1,\"strBattNo\":\"BAT-0001\",\"ActMass\":1.2,\"SpeCap\":3.4},{\"nBox\":2,\"nChl\":2,\"strBattNo\":\"BAT-0002\",\"ActMass\":1.2,\"SpeCap\":3.4}]}"
```

**停止 箱2 通道1（续接把 nOperaType 改 1，停止改 2）：**
```bash
curl -X POST http://172.16.28.132:7777/OpearMon/control -H "Content-Type: application/json" -d "{\"nOperaType\":2,\"MultipleChls\":[{\"nBox\":2,\"nChl\":1,\"strBattNo\":\"\"}]}"
```

返回示例：`{"nCode":0,"strMsg":"启动成功: 002_1,002_2"}`

### 7.3 接口二：查询通道状态 —— `POST /QueryChlStatus/control`
输入：无参数（空 JSON `{}`）。
```bash
curl -X POST http://172.16.28.132:7777/QueryChlStatus/control -H "Content-Type: application/json" -d "{}"
```
返回（实测，`strMsg` 内嵌 JSON）：
```json
{"nCode":0,"strMsg":"{\"AllChlStatus\":[{\"nBox\":1,\"nChl\":1,\"nStatus\":4}, ... {\"nBox\":2,\"nChl\":1,\"nStatus\":1},{\"nBox\":2,\"nChl\":2,\"nStatus\":1}, ...]}"}
```
`nStatus`：`0`测试中 `1`停止 `2`完成 `3`故障 `4`无状态。

### 7.4 接口三：查询实时参数 —— `POST /QueryChlRP/control`
输入：`vecAFO` 为空数组=查全部；或指定 `[{nBox,nChl},...]`。
```bash
curl -X POST http://172.16.28.132:7777/QueryChlRP/control -H "Content-Type: application/json" -d "{\"vecAFO\":[{\"nBox\":2,\"nChl\":1},{\"nBox\":2,\"nChl\":2}]}"
```
返回（实测）：
```json
{"nCode":0,"strMsg":"{\"ChlParam\":[{\"Cap\":0.0,\"Loop\":0,\"Curr\":0.0,\"Egy\":0.0,\"CexName\":\"BAT-0001_002_1\",\"Chl\":\"002_1\",\"Status\":1,\"StepNo\":0,\"StepSpan\":\"00:00:00\",\"Temperature\":0.0,\"StartTime\":\"...\",\"Volt\":0.0}, ...]}"}
```
字段：`Volt`电压 `Curr`电流 `Cap`容量 `Egy`能量 `Loop`循环 `StepNo`工步 `StepSpan`工步时间 `Temperature`温度 `StartTime`开始时间 `CexName`备份文件名 `Chl`通道标识 `Status`状态。

### 7.5 Python 最小可用客户端（放到 B 上即可运行，覆盖全部功能）
```python
# pip install requests
import json, requests

HOST = "172.16.28.132"   # ← A（蓝电主机）的IP
PORT = 7777
BASE = f"http://{HOST}:{PORT}"

def post(path, payload):
    r = requests.post(BASE + path, json=payload, timeout=5)
    r.raise_for_status()
    return r.json()

def arr(resp, key):     # 兼容 strMsg 内嵌 JSON
    if isinstance(resp.get(key), list): return resp[key]
    try:
        inner = json.loads(resp.get("strMsg", ""))
        return inner.get(key, [])
    except Exception:
        return []

# 1) 查询状态
st = post("/QueryChlStatus/control", {})
print("状态:", [(x["nBox"], x["nChl"], x["nStatus"]) for x in arr(st, "AllChlStatus") if x["nStatus"] != 4])

# 2) 启动 箱2 通道1（带电池条码）
r = post("/OpearMon/control", {
    "nOperaType": 0, "CycModeReverse": 0,
    "strBackupDir": r"D:\1", "strSpiFullPath": r"D:\1\LAND.spi",
    "SchemeFlag": "1210", "PartA": "",
    "MultipleChls": [{"nBox": 2, "nChl": 1, "strBattNo": "BAT-0001", "ActMass": 1.2, "SpeCap": 3.4}],
})
print("启动:", r.get("nCode"), r.get("strMsg"))

# 3) 查询实时参数
rp = post("/QueryChlRP/control", {"vecAFO": [{"nBox": 2, "nChl": 1}]})
for it in arr(rp, "ChlParam"):
    print("参数:", it["Chl"], "V=", it["Volt"], "I=", it["Curr"], "Cap=", it["Cap"])

# 4) 停止 箱2 通道1
r = post("/OpearMon/control", {"nOperaType": 2, "MultipleChls": [{"nBox": 2, "nChl": 1, "strBattNo": ""}]})
print("停止:", r.get("nCode"), r.get("strMsg"))
```

### 7.6 ⚠️ 请求限流（务必注意）
LANDMon 服务端有“防频繁请求”限流，请求过密会返回 `{"nCode":-1,"strMsg":"Reject frequent requests(QC)."}`。
**建议：相邻请求间隔 ≥ 1.2 秒；轮询状态/参数间隔 ≥ 5 秒；命中限流时退避等待 1~2 秒后重试。**
（本项目的图形上位机已内置节流与自动退避，用代码接入时请自行加间隔。）

## 8. SchemeFlag（备份文件名组合，4位数字）

| 位 | 取值 | 含义 |
|---|---|---|
| 第1位 | 0/1 | 启用/弃用 PartA(前缀) |
| 第2位 | 0/1/2/3 | 弃用PartB / 通道启动日期 / **电池条码** / 电池条码_通道启动时刻 |
| 第3位 | 0/1/2 | 弃用PartC / **通道号**(如 _002_8) / PartC_Alias |
| 第4位 | 0/1 | 顺序 AB_C / A_C_B |

默认 `1210` → 备份文件名形如 `电池条码_002_8`。

## 9. 排错速查

| 现象（B 上） | 原因 / 解决 |
|---|---|
| `Test-NetConnection` 为 False / curl 超时 | A 防火墙没放行 7777（第3节）；或 B 与 A 不同网段/IP填错（第2、4节） |
| “目标计算机积极拒绝” | A 上 LANDMon 没运行，或没绑定到该 IP（用第2.1节命令确认实际绑定IP） |
| 昨天能连今天连不上 | **A 的 IP 变了（DHCP）**。固定 A 的 IP（第2.2节），或重新用第2.1节查当前IP |
| 连上但看不到通道/全是“无状态” | 箱号选错，切到有效箱（现场为箱2） |
| 返回 `nCode=-1 Reject frequent requests` | 触发限流，加大请求间隔、退避重试（第7.6节） |
| 启动返回负数 nCode | `.spi` 路径在 **A 本机**不存在、通道已在测试、参数非法 |
| 跨网段不通 | 让 B 接到与 A 相同网段，或在路由器放通两网段路由 |

## 10. 接入前检查清单（Checklist）

- [ ] A：`LANDMon.exe` 已运行并连上测试柜(COM7)
- [ ] A：已确认 7777 绑定的 IP（`172.16.28.132`），并已**固定 IP**
- [ ] A：已添加防火墙入站放行 7777（第3节）
- [ ] B：与 A 同网段、IP 不冲突（示例 `172.16.28.100`）
- [ ] B：`Test-NetConnection A 7777` = True
- [ ] B：curl 调 `/QueryChlStatus/control` 能返回 JSON
- [ ] B：图形软件主机IP填 A 的IP、端口7777，显示“已连接”、箱号选到有效箱
- [ ] 代码接入：已加请求间隔（≥1.2s），轮询≥5s
